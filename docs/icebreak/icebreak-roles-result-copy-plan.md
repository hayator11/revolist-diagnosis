# Icebreak 33 11役割 結果コピーUX案

## 目的

このドキュメントは、`docs/icebreak/icebreak-roles-design-inventory.md` で棚卸しした11役割の既存設計を根拠に、Icebreak 33の結果表示へ将来使えるコピーUX案を整理するものです。

今回はドキュメント作成のみです。実装、UI、結果表示、URL、アルゴリズム、重み、`legacyResult`、`centeredResult`、API、GAS、Supabase、payload、設問データ、scriptsは変更しません。

## コピー作成の共通方針

- 役割名より先に「どんな働きをする人か」を伝える
- 「あなたはこうです」と断定しすぎず、「今回の回答では、この力が強く出ています」の余白を残す
- 名前の印象だけで書かず、mission / naturalActions / gives / receives / force / axis / question / 誤解しやすい点を根拠にする
- 短く、会話で使いやすい言葉にする
- オフ会や自己紹介で「自分はこういう動きが出やすいかも」と話せる形にする
- 低く出る傾向は評価ではなく、別の力を優先している情報として扱う

## 共通テンプレート案

```text
冒頭:
あなたは、〇〇する人。
今回の回答では、〇〇の力が強く出ています。

こんなところありませんか？
- 場面例1
- 場面例2
- 場面例3

本質:
あなたは〇〇を通して、場に力を生む人です。

気をつけたいクセ:
〇〇しすぎて、自分の力に気づきにくいことがあります。

オフ会での使い方:
〇〇な人と話すと、自分の良さが出やすいです。

シェア用:
私は、〇〇する人でした。
```

## 自己認識とズレた時の共通文

今回の結果は、あなたの全部を決めるものではありません。  
今の回答では、〇〇の力が強く出ています。  
もともと持っている別の力が、今回は〇〇という形で表れている可能性があります。  
しっくりくる部分と、少し違うと感じる部分の両方を、会話のきっかけとして使ってみてください。

## 11役割別コピー案

### revolist

- roleKey: `revolist`
- 表示名: レボリスト
- 冒頭の働きコピー: あなたは、まだ動いていない未来に最初の火を灯す人。
- 一言キャッチ: 最初の一歩で、場の空気を未来へ向ける人。
- こんなところありませんか？
  - 面白そうだと思うと、整う前でも小さく試したくなる
  - 誰かを待つより、自分が先に動く選択肢が浮かぶ
  - まだ見えていない未来を、言葉にして人へ渡したくなる
- 本質: あなたは未来への始動を通して、人が動ける起点を作る人です。
- 気をつけたいクセ: 先に火を灯す分、まだ準備中の人の速度を見落とすことがあります。
- オフ会での使い方: 「最近、少し始めてみたいことはありますか？」と聞くと、あなたの良さが出やすいです。
- 組むと動きやすい相手: ロジカルマイスター、アレンジャー、コミュニケーター、ソウルオーナー
- シェア用コピー: 私は、未来に最初の火を灯す人でした。
- 自己認識とズレた時の受け止め文: ふだん自分を行動派だと思っていなくても、今回の回答では「場を前に動かす起点」が強く出ています。大きく動く力ではなく、小さな一歩を置く力として見てみてください。

## 実装する場合の次工程

### データの置き場所候補

最初は既存ロジックから切り離し、コピー専用のデータとして追加するのが安全です。

候補:

- `src/data/icebreakRoleResultCopy.ts`
- `src/data/revo111RoleResultCopy.ts`

Icebreak 33専用で検証するなら `icebreakRoleResultCopy.ts` が自然です。将来Revo111にも使う前提なら、名前と責任範囲を再検討します。

### 接続方針

- まず結果表示に直接つながず、1役割だけ表示案を確認する
- 次に11役割分のデータ構造を固める
- `mainTypeKey` に応じてコピーを引く形にする
- `legacyResult` の判定自体は変えない
- `centeredResult` は表示タイプ決定には使わない

### 1役割だけ試すか、11役割一括か

初回実装では、1役割だけの試験接続が安全です。理由は、コピーの長さ、表示崩れ、ユーザーの受け取り方を小さく確認できるためです。  
ただしデータファイルは11役割分を先に持たせ、UI接続だけ1役割で試す方法が扱いやすいです。

### 実装前に確認すべきこと

- 結果ページでどのセクションに出すか
- 既存コピーと置き換えるのか、追加するのか
- 長文になりすぎないか
- スマホ表示で読みやすいか
- シェアカードに入れる文言はどれか
- 自己認識とズレた時の共通文を常時出すか、補足として出すか
