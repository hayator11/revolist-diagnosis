# Icebreak 33 中心0モデル 検証アンケート設計

## 目的

`centeredResultSummary` を表示に使う前に、人の感覚として納得できるか確認する。

同時に、現在表示に使っている `legacyResult` のしっくり度も確認する。

この検証では、診断結果がオフ会・マッチング・会話導線に使えるかを見る。

## 検証対象者

最初は、結果に対して感想を聞ける人から集める。

- 身近なテスター
- レボリストLab関係者
- オフ会参加者
- 運営メンバー
- 診断結果を見た後に、具体的な感想を聞ける人

## 回答後に聞く質問案

### 必須項目

1. 診断結果はどれくらいしっくりきましたか？
   - 1: まったく違う
   - 2: あまりしっくりこない
   - 3: どちらともいえない
   - 4: まあまあしっくりくる
   - 5: かなりしっくりくる

2. 結果のどの部分が自分らしいと感じましたか？

3. 結果のどの部分に違和感がありましたか？

4. この結果は、自己紹介や会話のきっかけに使えそうですか？
   - 1: 使えなさそう
   - 2: あまり使えなさそう
   - 3: どちらともいえない
   - 4: 使えそう
   - 5: かなり使えそう

5. この結果は、オフ会で人とつながるきっかけになりそうですか？
   - 1: なりにくい
   - 2: あまりなりにくい
   - 3: どちらともいえない
   - 4: なりそう
   - 5: かなりなりそう

6. もう少し知りたいと思った要素はありますか？

7. 自由コメント

### 任意項目

- 自分ではどんなタイプだと思いますか？
- 人からよく言われる特徴はありますか？
- 診断中に答えにくかった設問はありましたか？
- 「どちらでもない」を選んだ理由があれば教えてください
- 今後、マッチングや席替えに使われるなら抵抗はありますか？

## 集めない方がよい情報

検証に不要な個人情報やセンシティブな情報は集めない。

- 本名
- 住所
- 電話番号
- 健康情報
- 政治・宗教などセンシティブな情報
- 過度に個人的な情報

連絡先が必要な場合も、診断データとは分けて管理する。

## Googleフォーム化する場合の項目構成案

Googleフォームにする場合は、まず以下の最小構成でよい。

- 診断ID
- 回答日時
- 診断結果URL
- しっくり度
- 違和感
- 自分らしい点
- 会話に使えそうか
- オフ会マッチングに使えそうか
- 自由コメント

`centeredResultSummary` は、フォーム上で回答者に見せない。分析側で `diagnosisId` と紐づけて比較する。

## 分析時に見ること

しっくり度が低い人について、`legacyResult` と `centeredSummary` の差を見る。

`care / soulowner / movmentor` が出すぎていないかを見る。

`connect / design / ignite` が沈みすぎていないかを見る。

違和感コメントが特定タイプに集中していないかを見る。

答えにくい設問が特定問に集中していないかを見る。

会話導線として使えるという声があるかを見る。

オフ会やマッチングに使う場合、抵抗感が強く出ていないかを見る。

## まだやらないこと

実回答データの検証前に、以下は行わない。

- `centeredResultSummary` の表示反映
- `/api/feedback` への追加
- Google Apps Script連携変更
- 既存payload変更
- 重み変更
- 結果タイプ文言変更
