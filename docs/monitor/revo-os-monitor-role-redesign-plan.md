# Revo OS Monitor Role Redesign Plan

## 目的

公開前のモニター診断を、その場しのぎで文言だけ直すのではなく、最新のレボリスト診断思想に合わせて根本から再設計する。

現在の `/monitor` は、4診断 x 18問の同意式で構成されている。これは初期検証としては有効だったが、最新の33問シナリオ式診断とは設計思想が異なる。

今回目指すのは、単に11タイプを絞る診断ではない。

- その人が何を持ち寄る人なのか
- どんな場で役割が自然に出るのか
- どんな相手と可能性を引き出し合いやすいのか
- 選ばなかった選択肢からも、別の役割や必要な相手が見えること
- 答えながら、自分を見つめ返せること
- 楽しく、迷いすぎず、でも納得感が残ること

モニター版では、通常33問よりも多くの検証情報を集める。ただし、質問数を増やすこと自体を目的にしない。答える人が吸い込まれるように進められることを優先する。

## 現状との差分

### 現在の `/monitor`

- Revo Role / Team / Match / Growth の4診断
- 各18問
- 「当てはまる / 当てはまらない」の5段階回答
- `scores x 回答値` の単純加点
- 旧 `revotypes.ts` と `monitorResults.ts` の表現が中心
- 質問文が直接的で、何を測っているか想像しやすい
- 各質問が主に特定タイプの強弱を見る作り

### 最新方針

- 場面を選ぶA-E形式
- どの選択肢にも別の役割の手がかりを持たせる
- 「正解っぽい回答」を作らない
- 役割は優劣ではなく、持ち寄り方の違いとして扱う
- 「相性がいい人」ではなく「可能性を引き出し合いやすい相手」と表現する
- 結果は「あなたは何タイプ」だけでなく、「どう使うと力が出るか」「誰と組むと動きやすいか」まで返す

## 役割クラスター案

これはユーザーに固定表示する分類ではなく、設計者側が質問バランスを確認するための整理。

| クラスター | 役割 |
| --- | --- |
| 未来を生み出す側 | クレイジスト、レボリスト、マックスデザイナー、イメージマイスター |
| 翻訳・構造化する側 | ロジカルマイスター、インフォレイダー |
| 実行・運営へ移す側 | プルミエルクラフター、アレンジャー、ムーブメンター |
| 関係・安心を育てる側 | コミュニケーター、ソウルオーナー |

注意:

- この分類は優劣ではない
- 「希少派」「多数派」のように固定的に見せすぎない
- どの役割も、自分の役割に出逢ったときに力が開く
- ユーザー向けには「どこに属するか」より「何を持ち寄るか」を見せる

## モニター診断の新構成案

### 推奨: 44問シナリオ式

通常診断33問より多く情報を集めるため、公開前モニター版は44問を候補にする。

構成:

- 11役割 x 4観点
- 各問A-E選択
- 1問あたり5選択肢すべてが異なる役割・軸の手がかりを持つ
- 1つの回答が1タイプだけに直結しない

4観点:

1. 場で自然に見ているもの
2. 動き出すときの入口
3. 人と組むときの見方
4. 迷ったときに大切にするもの

これにより、単なる「あなたはどのタイプか」ではなく、以下が取れる。

- main role
- second role
- third role
- 可能性を引き出し合いやすい相手
- 活きやすい場
- チームでの持ち寄り方
- まだ表に出ていない補助役割
- 回答者が何に納得し、何に迷うか

## 質問設計原則

### 1. 測っている内容を想像させすぎない

避ける質問:

- 人をつなぐのが好きですか？
- 情報を調べるのが好きですか？
- 新しいことに挑戦したいですか？

採用する質問:

- 初対面の場で、少し静かな時間が流れました。自然に目がいくのは？
- 良い案が出たけれど、まだ動き出していません。あなたが置きたくなるものは？
- 誰かの中にある良さが、まだ本人に届いていないように見えます。自然にしたいのは？

### 2. 答えやすい場面にする

質問は「人格を問う」のではなく「場面で近い動きを選ぶ」形にする。

- 正しそうな答えを選ばせない
- 重すぎる内省にしない
- でも選んだあとに「たしかに自分はそうかも」と思える
- 初見でも意味がわかる
- A-Eのどれにも良さがある

### 3. どの回答にも複数の意味を持たせる

各選択肢には最低3種類の情報を持たせる。

```ts
type ScenarioChoiceScore = {
  directRoles: Partial<Record<RevoTypeKey, number>>;
  secondaryRoles: Partial<Record<RevoTypeKey, number>>;
  mirrorSignals: Partial<Record<RevoTypeKey, number>>;
  axisSignals: {
    self?: number;
    other?: number;
    field?: number;
    future?: number;
    structure?: number;
    expression?: number;
    care?: number;
    action?: number;
  };
};
```

意味:

- `directRoles`: その回答から自然に見える役割
- `secondaryRoles`: 表には出にくいが、同時に出ている補助役割
- `mirrorSignals`: その選択から見える「必要になりやすい相手」や「反対側にある役割」
- `axisSignals`: 自分・相手・場・未来・構造など、結果文に使う深い傾向

重要:

`mirrorSignals` はマイナス評価ではない。選ばなかった能力の欠落として扱わない。  
「この人が力を出すとき、近くにいると循環が起きやすい役割」として扱う。

## スコアリング方針

### 現行

```text
質問ごとの scores x 1-5
```

これは単純で分かりやすいが、以下の限界がある。

- 回答が強いほど特定タイプに寄る
- 質問の意図が見えやすい
- 1問1タイプの色が強くなる
- 「裏側の役割」や「組むとよい相手」が取りにくい

### 新方針

```text
選択肢ごとの direct / secondary / mirror / axis を合算する
```

例:

質問:

```text
アイデアがたくさん出て、少し散らかってきました。あなたがやりたくなるのは？
```

選択肢:

```text
A. もっと面白い可能性がないか広げる
```

スコア例:

```ts
directRoles: { maxdesigner: 3, crazist: 1 }
secondaryRoles: { revolist: 1 }
mirrorSignals: { logicalmaister: 2, arranger: 1 }
axisSignals: { future: 3, expression: 1 }
```

解釈:

- 本人の自然な動きは、可能性を広げる方向
- 同時に、実装時には構造化・配置役が近くにいると進みやすい
- 結果では「あなたの可能性を引き出し合いやすい相手」としてロジカルマイスターやアレンジャーを出せる

## モニターで集めたい検証情報

通常33問より深く集めるべき情報:

- 質問が楽しく選べたか
- どの設問で迷ったか
- どの選択肢が自分らしいと感じたか
- 結果の11役割名に納得できたか
- 役割説明が自分の言葉にしやすかったか
- 可能性を引き出し合いやすい相手に納得できたか
- 「自分の得意が伝わりにくかった理由」が見えたか
- オフ会やチームで使えそうか
- 結果を誰かに見せたいか
- もう少し知りたいと思った項目は何か

## `/monitor` ページの再設計案

現行の4診断カードは一度下げる。

新しい入口:

```text
レボリスト診断 公開前モニター

これは、あなたを分類する診断ではありません。
あなたが何を持ち寄り、
誰と可能性を引き出し合いやすいかを見つけるための
公開前テストです。
```

ページに置く内容:

- 44問・約7分
- A-Eの場面選択式
- 正解はない
- どの選択にも役割がある
- 結果では11役割、持ち寄れるもの、可能性を引き出し合いやすい相手が分かる
- 最後に感想フォームへつなぐ

## 実装フェーズ案

### Phase 1: 設計docs作成

このdocsを作り、方針を確定する。

### Phase 2: 11役割定義の統一

`revo111Roles.ts` / `icebreakRoleResultCopy.ts` / `/types` / `/monitor` の表示名・説明・相手候補を統一する。

### Phase 3: monitor question schema刷新

`monitorQuestions.ts` を旧18問x4診断から、新しいシナリオ式に変更する。

候補:

```ts
export interface MonitorScenarioQuestion {
  id: number;
  text: string;
  choices: MonitorScenarioChoice[];
}
```

### Phase 4: MonitorQuestion UI刷新

同意式の1-5ボタンを、A-E選択肢表示へ変更する。

### Phase 5: calculateMonitorResult刷新

`directRoles` / `secondaryRoles` / `mirrorSignals` / `axisSignals` を合算する。

### Phase 6: MonitorResultCard刷新

結果表示を以下へ変更する。

- あなたの11役割
- 役割の短い説明
- 持ち寄れるもの
- 活きやすい場
- 可能性を引き出し合いやすい相手 2-3タイプ
- 自分を見つめ返す問い
- 感想フォーム導線

### Phase 7: feedback刷新

モニターで本当に取りたい検証項目へ合わせる。

## まだ実装しないこと

- 旧4診断の即時削除
- 公開済み通常診断 `/diagnosis` の破壊的変更
- DB保存
- Supabase連携
- API変更
- 認証機能
- ユーザー履歴保存
- Revoコミュニティ登録導線の実装

## 結論

公開前に `/monitor` を見直すなら、入口文言だけを最新化するのでは足りない。

必要なのは、以下の根本再設計。

- 11役割の再定義
- 質問形式の刷新
- 回答1つに複数の意味を持たせるスコア設計
- 選ばなかった方向からも、必要な相手や補助役割が見える構造
- 楽しく選べて、答えながら自分を見つめ返せる設問
- 通常33問よりも検証情報が集まる44問モニター版

モニター版は、公開前の最終調整のための診断として、通常版より少し深く、でも重くなりすぎない設計にする。
