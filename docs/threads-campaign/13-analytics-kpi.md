# レボリスト診断 × Threads｜アナリティクス設計（KPI・ログ・改善サイクル）

> アカウント：Threads `@____hayator`
> 目的：発信（11タイプ）の効果を測り、**毎週まわる改善サイクル**をつくる。
> 前提：`00-strategy.md` の結論に完全準拠。
> - 2026年Threadsは**「いいね」より「返信（会話）」を最重視**。KPIの最上位も**返信**にする。
> - 初速（投稿後30〜60分）で拡散が決まる（4ステージ／Stage1が生命線）。
> - 3本柱 A（11タイプ紹介）／B（よくある特性）／C（組み合わせで能力アップ）。
> - トーンの鉄則：ネガティブ表現ゼロ／タイプに優劣なし。**測定の言葉づかいも同じ**（「外れた投稿」＝直すべき欠点、ではなく「次の仮説のタネ」）。
>
> **すべての数値目安は「初期の仮置き」です。** 最初の2〜3週の実データが集まったら、自分のアカウントの中央値に置き換えてください。目安は“合否ライン”ではなく“観測の出発点”です。

---

## 0. この設計の3行まとめ

1. 見る順番は **返信 → 初速 → 保存 → プロフ遷移 → 診断リンククリック → 診断実行**。返信を最上位に固定する。
2. 記録は**1投稿1行**のシンプルな表。手動で1分で書ける項目だけに絞る。
3. 毎週「伸びた投稿TOP3のフックと問い」を言語化して**翌週コピーする**。これが改善エンジン。

## 1. KPIツリー / ファネル

発信は「見られる」だけでは意味がなく、最終的に**診断が実行される**ところまでつなぐ。
ただしアルゴリズム上、**手前の“返信”を伸ばさないと後段の母数（リーチ）が増えない**ため、KPIは「返信を最上位」に置く構造にする。

### 1.1 ファネル全体像

```
　　　　　　　　　　　（アルゴリズムを動かす層＝まず勝つべき所）
[1] インプレッション / リーチ … どれだけ表示されたか（結果指標・母数）
        ▲ これを増やす“原因”が ↓
[2] 返信数　★最重要KPI　　　　… 会話が起きたか（Stage1突破の鍵）
[3] 保存・シェア　　　　　　　　… 役立つ／見せたい（拡散の燃料）
        │
        ▼（ここから事業KPI＝診断につなぐ層）
[4] プロフィール遷移　　　　　　… 「この人を知りたい」に転換したか
[5] 診断リンククリック　　　　　… bio/固定リンクを踏んだか
[6] 診断実行（開始→完了）　　　… サイトに着地し、診断されたか
```

> ポイント：**[2]返信は「最上位KPI」だが、ファネルの最終ゴールではない**。
> 返信＝アルゴリズムを突破して[1]の母数を増やすための“エンジン”。
> エンジン（返信）で母数を増やし、その母数を[4]〜[6]で診断へ流す、という二段構え。

### 1.2 各段の指標・見る理由・初期の仮置き目安

| # | 指標 | 何を表すか | なぜ見るか | 初期の仮置き目安 | 取得元 |
|---|------|-----------|-----------|----------------|--------|
| 1 | インプレッション / リーチ | 表示回数・到達人数 | 後段すべての母数。単体では追わず「返信が増えたら伸びる結果」として見る | まずは自分の直近中央値を基準線に（例：フォロワー数の3〜10倍/投稿） | Threadsインサイト |
| 2 | **返信数 / 投稿**　★ | 会話が起きたか | **2026アルゴリズムの最重要シグナル**。Stage1突破＝おすすめ拡散の入口 | **1投稿あたり3件以上**（まず“最初の3返信を60分以内”） | 手動カウント＋インサイト |
| 2b | 返信率（返信数 ÷ リーチ） | 表示に対する会話の濃さ | 母数が伸びても薄い会話だと拡散が続かない。質の指標 | **1.0%以上**（例：リーチ300で3返信） | 計算 |
| 2c | 初速：60分以内の反応数 | 投稿直後の勢い | Stage1は初速で決まる。ここが全ての起点 | **60分で反応3件以上／うち返信1件以上** | 投稿後に手動チェック |
| 3 | 保存数 | 「後で見たい／役立つ」 | 拡散の燃料。まとめ・ランキングで最大化 | まとめ系で**リーチの0.5%以上**を目安に観測開始 | インサイト |
| 3b | シェア（リポスト/引用/DM共有） | 「人に見せたい」 | 自走的な拡散。タグ付け遊びで誘発 | 参考指標（まず有無を記録） | インサイト |
| 4 | プロフィール遷移 | 投稿→アカウントへの興味転換 | 事業KPIの入口。診断への唯一の橋 | **リーチの1〜3%**を観測開始ラインに | インサイト |
| 5 | 診断リンククリック | bio/固定リンクのクリック | 遷移が“行動”に変わったか | **プロフ遷移の10〜20%** | リンク計測（下記2.3） |
| 6 | 診断開始→完了 | サイト着地後の実行 | 最終ゴール。発信が事業に効いた証拠 | 完了率**クリックの30%以上**を観測開始 | サイト解析（下記2.3） |
| — | フォロワー増 | 定着の遅行指標 | 参考のみ。**返信を優先**（追いかけすぎない） | 週次で増減の傾向だけ見る | インサイト |

### 1.3 「北極星」と補助指標

- **North Star（週次で1つだけ選ぶなら）**：**返信率（返信数 ÷ リーチ）**。
  - 生の返信数はリーチが増えると自然に増えるため、**率**で会話の“濃さ”を見る。
- **事業のNorth Star（月次）**：**診断実行数（週合計）**。
  - 発信全体が事業に効いているかの最終判定。SNS単体ではなく、遷移→クリック→実行の連鎖で見る。

## 2. 記録の仕組み（手動運用でまわる軽さ）

### 2.1 スプレッドシート「投稿ログ」列定義（1投稿＝1行）

そのままGoogleスプレッドシート／Notionのテーブルに貼れる列。**太字＝毎回必ず埋める必須列**、それ以外は任意（余裕があるとき）。

| 列名 | 型 | 入力例 | メモ |
|------|----|-------|------|
| **post_id** | 文字 | `A-01` | 柱＋通番（例 A-01, B-03, C-02）。02-posts.md のコピー番号と対応 |
| **date** | 日付 | `2026-07-15` | 投稿日 |
| **time** | 時刻 | `12:30` | 投稿時刻（昼/夜の検証に使う） |
| **weekday** | 選択 | `火` | 曜日（水木金がやや強い仮説の検証用） |
| **pillar** | 選択 | `A` | 柱：A / B / C |
| **format** | 選択 | `画像カルーセル` | `画像カルーセル` / `画像1枚` / `テキスト` / `ハイブリッド` |
| **theme** | 文字 | `レボリスト紹介` | 何の投稿か（タイプ名やお題） |
| **hook_type** | 選択 | `意外な事実` | フック種別（下の凡例） |
| **hook_text** | 文字 | `“最初に動いちゃう人”、実はこういう才能です。` | 1行目そのまま |
| **closing_question_type** | 選択 | `自己言及型` | 締めの問い種別（下の凡例） |
| **closing_question_text** | 文字 | `あなたは何タイプだと思う？` | 末尾の問いそのまま |
| **cta_type** | 選択 | `なし` | `なし`/`プロフ誘導`/`コメント誘導`/`診断リンク`。Week4まで診断CTAは控えめに |
| **first60_reactions** | 数値 | `4` | ★**初速**：投稿後60分の反応合計 |
| **first60_replies** | 数値 | `2` | ★初速のうち返信数 |
| **replies_total** | 数値 | `7` | ★**返信数（最終／記録時点）** |
| **saves** | 数値 | `5` | 保存数 |
| **shares** | 数値 | `1` | リポスト＋引用＋DM共有 |
| **likes** | 数値 | `31` | 参考（弱いシグナル） |
| **reach** | 数値 | `520` | リーチ or インプレッション（どちらか固定して統一） |
| reply_rate | 数式 | `=replies_total/reach` | 自動計算（%表示） |
| profile_taps | 数値 | `9` | プロフィール遷移数 |
| link_clicks | 数値 | `2` | 診断リンククリック（計測できる範囲で） |
| replied_all | 選択 | `Yes` | 全返信に返したか（初速オペ実行チェック） |
| ig_story | 選択 | `Yes` | Instagramストーリーズ同時告知したか |
| ab_tag | 文字 | `T-昼` | A/Bテストの実験タグ（後述4章。無ければ空欄） |
| note | 文字 | `質問が具体的で返信伸びた` | ひとことメモ（伸び/学びの気づき） |

> **最小構成（時間がない日）**：`post_id / date / pillar / format / hook_type / closing_question_type / first60_replies / replies_total / saves / reach / note` の11列だけでも回る。まずここから。

**hook_type 凡例**：`断定` / `意外な事実` / `問い` / `あるある共感` / `ストーリー` / `ランキング・数字`
**closing_question_type 凡例**：`自己言及型`（あなたは何タイプ？）/ `共感確認型`（わかる人？）/ `選択型`（どっち？）/ `指名型`（誰と組みたい？）/ `タグ付け型`（〇〇な友達をタグ付け）

### 2.2 集計タブ（自動でOK・任意）

投稿ログとは別シートに、柱別・形式別・問い別の平均を出しておくと週次が楽。
- 柱別：`AVERAGEIF(pillar, "A", reply_rate)` のように A/B/C の平均返信率・平均保存・平均プロフ遷移
- 形式別：画像 vs テキスト vs ハイブリッドの平均返信率／平均リーチ
- 問い別：closing_question_type ごとの平均返信数（どの問いが会話を生むか）

### 2.3 診断リンク・診断実行の計測（軽量な方法）

過剰なツールは不要。手動運用の範囲でできる順に。

1. **リンクに識別子を付ける（最優先・無料）**：bioや固定リンクを
   `https://…/diagnosis?src=threads` のようにUTM風パラメータ付きにする。
   → サイト側の解析（Vercel Analytics 等）で `src=threads` の流入・診断開始数が分かる。
   投稿ごとに分けたい時は `?src=threads&p=A-01` のように post_id を足す。
2. **プロフ遷移・リンククリックはThreadsインサイトの数字を手入力**（週1でまとめて）。
3. **診断実行数はサイト側で週次集計**（開始/完了。既存のVercel/計測で追える範囲でOK）。
4. 個別投稿ごとの正確なクリック紐付けが難しい日は、**週合計だけ**でも十分に傾向は見える。

## 3. 週次レビュー様式

毎週15〜20分。目的は**「勝ちパターンを言語化して翌週コピーする」**こと。
数字の反省会ではなく、**再現できる型を1つ増やす**会。

### 3.1 テンプレート（コピペ用）

```
# 週次レビュー：Week __（YYYY-MM-DD 〜 YYYY-MM-DD）

## サマリー（今週の数字）
- 投稿数：__本（A:__ / B:__ / C:__）
- 平均返信数：__　／　平均返信率：__%（★North Star）
- 60分以内に最初の返信がついた投稿：__ / __本
- 全返信に返した投稿（初速オペ実行率）：__ / __本
- 保存合計：__　／　プロフ遷移合計：__　／　診断リンククリック：__
- 診断実行（週合計）：__

## 伸びた投稿 TOP3（★ここが本体）
1) post_id：____　柱：__　形式：__
   - フック（hook_text）：「____」→ なぜ効いた？：____
   - 締めの問い（closing_question_text）：「____」→ なぜ会話が起きた？：____
   - 数字：返信__ / 保存__ / プロフ遷移__
   - 翌週の再利用アクション：____（例：この問いの型を別タイプでも使う）
2) …
3) …

## 学びになった投稿（伸び切らなかったもの／ネガに書かない）
- post_id：____　気づき：____（例：問いが抽象的で答えづらかった → 次は選択式に）
- ※「失敗」ではなく「次の仮説のタネ」として書く

## 実験の結果（A/Bテスト・4章）
- 今週の検証変数：____（1つだけ）
- 結果：____　→　暫定結論：____

## 来週の仮説（3つまで）
- 仮説1：____（例：昼12時台の画像投稿はプロフ遷移が伸びる）
- 仮説2：____
- 仮説3：____

## 来週やること（TOP3のコピー＋新規実験1つ）
- [ ] TOP3で効いた「問いの型」を __本 に再利用
- [ ] 新しい実験：__（1変数だけ）
- [ ] 初速オペ（60分張り付き）を全投稿で徹底
```

### 3.2 記入例（サンプル）

```
# 週次レビュー：Week 2（2026-07-08 〜 2026-07-14）

## サマリー（今週の数字）
- 投稿数：9本（A:4 / B:3 / C:2）
- 平均返信数：5.1　／　平均返信率：1.3%（★先週0.8%から改善）
- 60分以内に最初の返信がついた投稿：7 / 9本
- 全返信に返した投稿：8 / 9本
- 保存合計：38　／　プロフ遷移合計：61　／　診断リンククリック：11
- 診断実行（週合計）：7

## 伸びた投稿 TOP3
1) post_id：B-04　柱：B　形式：テキスト
   - フック：「“頼まれてないのに整えちゃう人”いる？」
     → なぜ効いた？：一人称の“あるある”で自分ごと化。名指しせず共感だけ誘った
   - 締めの問い：「これ、わかるって人？」（共感確認型）
     → 答えるハードルが最小。ワンタップで“わかる”と書ける
   - 数字：返信12 / 保存6 / プロフ遷移14
   - 翌週の再利用：この「“〜しちゃう人いる？”＋共感確認型」の型を別タイプで3本作る
2) post_id：A-02　柱：A　形式：画像カルーセル
   - フック：「色で分かる、あなたの動き方。」
     → 表紙の色が強く、スワイプ滞在が伸びた
   - 締めの問い：「あなたは何タイプだと思う？」（自己言及型）
     → プロフ遷移が今週最多。診断への橋になった
   - 数字：返信7 / 保存11 / プロフ遷移22
   - 翌週の再利用：画像アンカー投稿の締めは自己言及型で固定する
3) post_id：C-01　柱：C　形式：ハイブリッド
   - フック：「相性がいい2人でも、止まる時がある。」
   - 締めの問い：「あなたの相方は11タイプの誰？」（指名型）
   - 数字：返信8 / 保存4 / プロフ遷移9
   - 翌週の再利用：指名型は会話が伸びる。組み合わせ投稿の定番にする

## 学びになった投稿
- post_id：B-05　気づき：問いが「どう思う？」で抽象的すぎた。返信2どまり。
  → 次は「AとB、どっち？」の選択型に変えて答えるハードルを下げる（仮説へ）

## 実験の結果
- 今週の検証変数：締めの問い（共感確認型 vs 自己言及型）
- 結果：返信数は共感確認型が上（答えやすい）／プロフ遷移は自己言及型が上（診断につながる）
  → 暫定結論：会話を稼ぐ日はB柱で共感確認型、遷移を狙う日はA柱で自己言及型と使い分け

## 来週の仮説
- 仮説1：選択型の問いは共感確認型に迫る返信数が出る（B-05の反省から）
- 仮説2：昼12時台の画像投稿はプロフ遷移が伸びる（A-02が昼だった）
- 仮説3：指名型（タグ付け含む）はシェアが増える

## 来週やること
- [x] 「“〜しちゃう人いる？”＋共感確認型」を別タイプで3本
- [ ] 新実験：締めの問い＝選択型 を3本でテスト（1変数）
- [ ] 全投稿で初速60分張り付きを継続
```

## 4. A/Bテスト計画（軽量・1度に1変数）

手動運用なので**厳密なABではなく「1変数ずつ、数本ためして傾向を見る」ゆる検証**でよい。
鉄則は**「1度に変えるのは1つだけ」**。同時に複数変えると、何が効いたか分からなくなる。

### 4.1 進め方（4ステップ）

1. **変数を1つ選ぶ**（下の系統から）。
2. **他を揃える**（同じ柱・近い時間帯・同じくらいのテーマの重さ）。
3. **各パターン3〜5本ずつ**投稿し、`ab_tag` 列にラベルを付ける（例：`Q-共感` / `Q-自己言及`）。
4. **週次で平均を比較**→勝ちパターンを翌週の“標準”に採用。負けた方は保留（捨てずに別条件で再検証）。

> 少数本での差は「確定」ではなく「傾向」。**2週続けて同じ傾向なら採用**、を目安に。

### 4.2 検証する4系統（優先順）

| 優先 | 変数 | パターン例 | 主に見る指標 | メモ |
|------|------|-----------|-------------|------|
| 1 | **締めの問いのタイプ** | 共感確認型 / 自己言及型 / 選択型 / 指名型 | **返信数・返信率**（＋自己言及型はプロフ遷移も） | 最重要。返信に直結する変数から始める |
| 2 | **形式（画像 vs テキスト）** | 画像カルーセル / テキスト主体 | 返信率 と リーチ の両方 | `00-strategy §1.5`：画像は保存・滞在、テキストは返信。**柱ごとの推奨形式が前提**なので柱を揃えて比較 |
| 3 | **投稿時間** | 昼12〜14時 / 夜20〜22時 | 初速60分反応・返信率 | 同じ柱・同じ問いタイプで昼夜を振る |
| 4 | **フック種別** | 断定 / 意外な事実 / あるある共感 | 初速60分反応・返信率 | 1行目だけ変えて中身は近づける |

### 4.3 実験カレンダー例（1変数＝1〜2週）

```
Week A：締めの問い（共感確認型×3本 vs 自己言及型×3本）… ab_tag=Q-共感 / Q-自己言及
Week B：形式（B柱を テキスト×3 vs 画像1枚×3）      … ab_tag=F-text / F-img
Week C：投稿時間（同条件で 昼×3 vs 夜×3）           … ab_tag=T-昼 / T-夜
Week D：フック（意外な事実×3 vs あるある共感×3）     … ab_tag=H-意外 / H-あるある
```

> 走らせない週があってもよい。**実験は「効きそうな1変数」だけ**でも十分に学びが貯まる。

## 5. 各柱の「成功の定義」

柱ごとに役割が違うので、**追う主指標を分ける**。全部を1つの物差しで測らない。
（返信は全柱共通の“最重要土台”。その上で柱ごとの主指標を重ねる）

| 柱 | 目的（00-strategy） | 推奨形式 | **主指標（成功の定義）** | 補助指標 | ひとことで言うと |
|----|--------------------|---------|------------------------|---------|----------------|
| **A. 11タイプ紹介** | 認知・自分ごと化 | 画像カルーセル | **保存数** ＋ **プロフィール遷移** | リーチ・滞在・診断リンククリック | “保存されて、興味を持たれたら勝ち” |
| **B. よくある特性** | 共感・会話 | テキスト主体 | **返信数・返信率** | いいね・共感コメントの質 | “会話（返信）が量産できたら勝ち” |
| **C. 組み合わせで能力アップ** | 参加・巻き込み | ハイブリッド | **参加コメント数（指名・タグ付け）** ＋ **シェア** | 返信ラリーの往復数 | “巻き込みで自走したら勝ち” |

### 5.1 柱別の初期の仮置き目安（観測の出発点）

| 柱 | 主指標の仮置きライン（初期） |
|----|--------------------------|
| A | 保存 ≥ リーチの0.5% ／ プロフ遷移 ≥ リーチの2% |
| B | 返信 ≥ 5件／投稿 ・ 返信率 ≥ 1.2% |
| C | 指名・タグ付け系コメント ≥ 3件 ／ シェア ≥ 1件 |

> いずれも**最初の仮置き**。2〜3週の自分の中央値が出たら、その値を基準線に更新する。

### 5.2 柱をまたぐ共通の合格ライン（全投稿）

- **60分以内に最初の返信が付く**（初速オペの成否）。
- **全返信に返した（replied_all = Yes）**。
- ネガティブ表現ゼロ・タイプに優劣をつけていない（トーンチェック）。

## 6. 運用リズム（まとめ）

| タイミング | やること | 所要 |
|-----------|---------|------|
| 投稿直後〜60分 | 初速オペ（自分で最初のコメント→全返信に返す→IGストーリー告知） | 常時 |
| 投稿から数時間後 | ログに `replies_total / saves / reach` などを追記 | 1分 |
| 毎週（例：日曜） | 週次レビュー（3章テンプレ）→ TOP3の型を翌週へ／実験の結論 | 15〜20分 |
| 隔週〜月次 | 仮置き目安を自分の中央値へ更新／North Star（返信率・診断実行）の推移確認 | 20分 |
