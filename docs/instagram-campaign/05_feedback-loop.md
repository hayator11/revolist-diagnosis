# 05｜フィードバックループ（反応を見てアップデートする仕組み）

このOSの中核。**数値を読む → 打ち手を決める → 次に反映する** の翻訳表。
「反応を見ながらアップデート」を、感覚ではなく再現可能な手順にする。

---

## A. 何を計測するか（インサイトのどこを見るか）

Instagramインサイト（各投稿の「インサイトを見る」）から、毎回この数字を拾う。

| 指標 | インサイト上の名称 | 計算 | 意味 |
|------|-------------------|------|------|
| リーチ | リーチ / アカウント数 | — | 何人に届いたか |
| **保存率** | 保存 ÷ リーチ | % | 内容の価値（最重要） |
| **送信率** | シェア（送信/DM） ÷ リーチ | % | 拡散の起爆力（新規リーチを生む） |
| 完読率 | カルーセル最終カード付近のリーチ ÷ 1枚目 | % | フックと構成の強さ |
| プロフCTR | プロフィールへのアクセス ÷ リーチ | % | 診断への入口が機能したか |
| リンククリック | 外部リンクのタップ数 | 数 | 実際に診断へ進んだ量 |
| フォロー | この投稿経由のフォロー | 数 | 新規獲得 |

> リールは「視聴維持率（平均視聴時間）」と「リーチ」も併記。
> 数字は投稿から**3〜7日おいて固まってから**記入する（初日は伸び途中）。

### 目安（この線を基準に判断）
- 保存率 **3%以上＝優秀** / 1.5%未満＝要改善
- 完読率 **50%超＝良い**
- 送信率は高いほど良い（1回のDM送信 ≒ いいね約15回の配信価値）

---

## B. 意思決定マトリクス（数値パターン → 打ち手）

週次レビューで、各投稿・全体の数字をこの表に当てはめて来週を決める。

| 観測された反応 | 解釈 | 打ち手（来週こうする） |
|--------------|------|---------------------|
| 保存率 高 ＆ リーチ 高 | **勝ち筋** | 同じテーマ/型を翌週2本に増やす。リール化して発見を拡大 |
| 保存率 高 ＆ リーチ 低 | 中身は良い・発見が弱い | フックとカバーを強化、リールで露出、投稿時間を変える |
| リーチ 高 ＆ 保存率 低 | 目は引くが刺さってない | テーマ or チートシート(要約スライド)を作り直す |
| 完読率 低（後半で離脱） | 冒頭の引きが弱い | 1〜3枚目のフック/テンポを直す、途中に5秒動画を挟む |
| 送信率 高 | 拡散燃料 | "友達に送りたくなる"あるある/相性ネタを増幅 |
| コメント多い | 巻き込み成功 | 問いかけ型キャプションを標準化、コメントに全返信 |
| プロフCTR 低 | 診断への導線が弱い | 最終スライドCTAとプロフ（ハイライト/リンク）を見直す |
| リンククリック 低（プロフCTRは高い） | プロフで止まっている | プロフ文＋リンク位置を診断直行に最適化 |
| フォロー増 停滞 | シリーズ感/一貫性不足 | 保存版・連番シリーズを増やし「続きが見たい」を作る |
| 特定タイプの反応が突出 | そのタイプに需要 | 単独深掘り（あるある/相性/職業別）で派生ネタを量産 |

## C. 実験の回し方（A/B・1回1変数）

「なんとなく変える」を防ぐため、**1週間に試す変更は1つだけ**。2週回して判定。

| 実験対象 | Aパターン | Bパターン |
|---------|----------|----------|
| フックの言い回し | 疑問形「こういう人いない？」 | 断定「実は〇〇の証拠です」 |
| カバーの色 | キーカラー塗りつぶし | 濃紺(Revo Ink)＋差し色 |
| テーマ | タイプ紹介 | あるある集 |
| 投稿時間 | 平日夜(21時台) | 週末昼(12時台) |
| 枚数 | 8枚 | 10枚 |

**判定ルール**：勝敗は「保存率＋送信率」で見る。勝ったパターンを標準に採用し、次の実験へ。
結果は `content-log.csv` の notes と `backlog.md` の「学びメモ」に必ず残す（同じ実験を繰り返さない）。

---

## D. 増幅と停止のルール（勝ち筋を育て、負け筋を寝かせる）

- 🟢 **昇格**：2投稿連続で保存率が基準(3%)を超えた型 → 「勝ちフォーマット」に昇格し、定番シリーズ化
- 🟡 **維持**：基準前後をうろつく型 → フックだけ変えて継続テスト
- 🔴 **停止**：3投稿連続で基準の半分(1.5%)未満 → 一旦アーカイブ（"失敗"ではなく"寝かせる"。切り口を変えて後日再挑戦）

> 停止は否定ではない。診断の原則どおり、ネガティブに扱わず「今は寝かせる」と記録するだけ。

## E. 週次レビュー記入フォーム（コピペして埋める）

毎週これを埋めれば、AI部長が意思決定マトリクスで来週を返します。

```
◆ 今週のレビュー（YYYY-MM-DD週）
投稿数：カルーセル__本 / リール__本 / ストーリーズ__枚

【数字トップ3（保存率順）】
1. [テーマ/タイプ] 保存率__% 送信率__% リーチ____
2. ...
3. ...

【数字ワースト】
- [テーマ/タイプ] 保存率__% 送信率__% リーチ____

【全体】フォロワー増__ / プロフ訪問__ / リンククリック__

【4つの問い】
・一番伸びたのは？
・なぜ？（仮説）
・沈んだのは？なぜ？
・来週変えることは？

→ AI部長へ：この数字から来週の3決定（増やす/やめる/実験）をください
```

## F. ループが閉じているかのチェック

このループが機能している証拠 ＝ 以下が毎週起きていること。
- [ ] 全投稿がログ（content-log.csv）に記入されている
- [ ] 保存率トップ/ワーストを毎週特定している
- [ ] 「来週の3決定」が言語化され、バックログに反映されている
- [ ] 実験が1つ走っていて、結果が記録されている
- [ ] 予約枠に7日分以上ストックがある

1つでも欠けたら、そこがループの詰まり。まずそこを直す。
